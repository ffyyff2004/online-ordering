# 订单操作与权限

## 使用

更新后管理员和用户需要重新登录。管理员进入“订单信息列表”，用户进入“我的订单”。

- 待付款：用户或管理员可取消。管理员须填写原因。
- 已付款、已接单、制作中：管理员取消订单后进入退款中，不直接标记已取消。
- 配送中：管理员可完成订单，或填写原因取消配送；取消配送恢复为制作中，可重新配送。需终止订单时，再取消订单并审核退款。
- 用户仅可在已付款、已接单时申请退款，需填写原因。
- 退款中：管理员可同意或拒绝，需填写审核备注。同意后为已退款；拒绝后恢复申请前状态。
- 旧的退款中订单没有申请记录时不能自动拒绝恢复，避免猜测原状态；可以确认模拟退款。
- 已取消、已退款、已完成不允许再次推进或取消。
- 双方可在操作记录中查看状态变化与原因。记录仅覆盖升级后的操作，不伪造历史记录。

付款及退款仍为本地模拟，不接入支付宝、微信或银行，不产生真实资金交易。

## 权限与保留数据

管理员接口需要服务器端管理员登录会话；普通用户订单接口需要用户会话。用户编号由服务器读取，不信任页面传入的编号。用户只能查询及操作自己的订单、订单明细、购物车和操作记录。

订单变更只接受 POST，拒绝跨站请求、重复提交及不允许的状态变更。状态与操作记录在同一数据库事务中写入，并锁定订单以避免并发覆盖。原来的直接编辑、删除订单和明细接口被禁用，避免绕过审核或破坏记录。订单查询不再携带用户密码。

启动时执行 resources/db/order-workflow.sql，仅创建缺失的 order_events 表，不清空已有订单、账号或菜单。无需重新导入根目录的完整 SQL 文件。

本次权限检查覆盖订单相关功能和管理接口，不代表已完成整个旧项目的全面安全审计。

## 验证

在 vue_wsdcxt 目录执行：

~~~powershell
mvn test
node --test src/test/js/smart-meal.test.cjs src/test/js/order-workflow.test.cjs
~~~

数据库集成测试创建临时测试订单并自动回滚，验证取消、撤销配送、退款审核、角色、订单归属、跨站请求和旧接口封锁。不要对真实用户订单手动执行演示付款或退款来测试。
